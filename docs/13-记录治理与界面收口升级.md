# 13 记录治理与界面收口升级

本文记录本轮继续升级的范围，用于承接用户“严格按照之前具体要求完整实现后再停止”的要求，避免后续迭代遗漏。

## 01 本轮对应的用户要求

| 用户要求 | 本轮处理 |
| --- | --- |
| 页面不要太冗杂，记录可以折叠，需要时再展开 | 评测历史、审计历史、证据分析历史改为折叠式记录；长列表容器增加局部滚动 |
| 记录可以删除管理 | 新增评测记录、审计运行记录、证据分析记录删除接口和前端删除按钮 |
| 不减少功能，只清爽化界面 | 保留打开、下载、归档、复核、控制测试、证据请求、评测门禁等能力，只调整信息密度和管理方式 |
| 产品网站只给客户使用，不展示市场/JD研究 | 本轮未把市场关注方向写入网站；相关趋势仍保留在内部文档 `docs/12-Agent市场关注方向内部参考.md` |
| Harness、自进化、评测、Tool Use 要继续完整 | 删除能力接入运行治理链路，并通过测试覆盖，避免运行数据越积越乱 |
| 每轮升级后记录文档并用 git 保存 | 本文档作为本轮记录，完成验证后提交到当前 git 分支 |

## 02 后端新增能力

新增持久化记录删除能力：

- `EvaluationRunRepository.delete_run(run_id)`
- `AuditRunRepository.delete_run(run_id)`
- `EvidenceAnalyzer.delete_analysis(analysis_id)`

新增 API：

```http
DELETE /api/evaluation/runs/{run_id}
DELETE /api/audit/runs/{run_id}
DELETE /api/evidence/analyses/{analysis_id}
```

这些接口返回统一结构：

```json
{
  "success": true,
  "deleted": "记录 ID",
  "timestamp": "删除时间"
}
```

## 03 前端体验升级

### 3.1 评测页

- 评测历史由普通卡片改为 `details` 折叠记录。
- 每条记录保留发布门禁状态、得分、通过率、回归数、基线信息。
- 每条记录新增删除按钮，删除后自动刷新历史。

### 3.2 审计页

- 审计档案历史改为折叠记录。
- 每条记录提供“打开”和“删除”两个明确动作，避免整张卡误触。
- 删除当前打开的审计项目时，会同步清空下载链接、阶段卡片和结果区域，避免用户下载已不存在的报告。

### 3.3 证据分析历史

- 证据分析历史改为折叠记录。
- 每条记录提供“打开”和“删除”动作。
- 删除当前打开的证据分析时，会清空当前分析面板并提示记录已删除。

### 3.4 长列表收口

以下容器增加局部滚动，减少整页长下拉：

- 评测历史
- 审计档案历史
- 证据分析历史
- 证据请求中心
- 控制测试工作台
- 整改任务跟踪

## 04 测试覆盖

新增/更新测试点：

- 评测记录创建后可删除，删除后 `get_run` 返回空。
- 审计记录创建后可删除，删除后 `get_run` 返回空。
- 证据分析记录创建后可删除，删除后 `get_analysis` 返回空。

本轮验证命令：

```powershell
node --check static\training.js
node --check static\audit.js
python -m compileall -q agents services rag web tests training
python -m unittest discover -s tests -p "test_*.py"
```

## 05 后续仍需持续关注

这些不是本轮新增市场展示，而是内部演进方向，后续继续按用户要求补强：

1. 继续检查页面文字重合、移动端拥挤和局部滚动体验。
2. 继续提升 Agent/RAG 评测的增量评测、缓存命中和并发执行效率。
3. 继续增强 Harness 的失败样本沉淀、回归阻断、自动修复建议和一键任务化能力。
4. 继续增强 Tool Use 的选择理由、权限边界、失败归因和恢复策略。
5. 继续把市场关注方向记录在内部文档，不写入客户网站。
