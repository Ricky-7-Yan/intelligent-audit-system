## 2. 按公司准备策略

### 2.1 字节跳动 / 飞书 / Seed / 番茄

高频画像：

- Agent 框架和协议：LangChain、LangGraph、AutoGen、MCP、A2A、Function Calling。
- Memory：上下文压缩、长期记忆、画像记忆、相关历史召回。
- RAG：切块、查询改写、混合检索、重排、引用、评估。
- 后端工程：FastAPI、SSE、异步任务、接口设计、日志、权限。
- 项目拷打：是否真实落地、是否只是 demo、怎么证明效果。
- 手撕题：数组、矩阵、字符串、HashMap、动态规划。

AuditPilot 推荐讲法：

> 我把 Agent 能力放在审计交付链路中，而不是只做对话。底层自研 Plan/Execute/Reflect Runtime，抽象上类似 LangGraph 的状态图，但每一步都绑定审计产物、工具调用、反思和质量门。这样面试时能解释状态协议和失败恢复，生产上也能迁移到 LangGraph 或 Temporal。

字节高频追问与回答：

| 追问 | 回答抓手 |
| --- | --- |
| 你为什么不用 LangGraph？ | 自研 Runtime 是为了展示协议和状态；生产复杂图可以迁移。 |
| Memory 怎么压缩？ | Working 保序，Episodic 摘要，Profile 结构化，Related 召回；审计实体优先保留。 |
| MCP 和 Function Calling 区别？ | Function Calling 是模型输出调用；MCP 是 Host/Client/Server 协议；Skill 是工程治理单元。 |
| RAG 怎么防幻觉？ | 来源、置信度、质量门、missing evidence、人审、评测。 |
| Agent 怎么避免乱调用工具？ | Schema、权限、工具描述、路由置信度、安全门、工具日志和熔断。 |

### 2.2 腾讯 / 混元 / WXG / TEG

高频画像：

- 测试开发：接口测试、自动化测试、压测、质量体系。
- 大模型评测：准确性、稳定性、安全性、鲁棒性、badcase。
- 后端基础：缓存、数据库、并发、消息队列、服务治理。
- 观测定位：日志、trace、metrics、报警、问题归因。
- 工具可靠性：超时、重试、熔断、降级。

AuditPilot 推荐讲法：

> 我在项目里没有只关注模型输出，而是做了 Agent/RAG/Deep Research 三类评测，评测结果进入 Evaluation Repository，并和历史基线对比。发布门禁会看质量回归、延迟回归、通过率和 blocker，这和大模型测试开发岗位关注的质量体系比较一致。

腾讯高频追问与回答：

| 追问 | 回答抓手 |
| --- | --- |
| 大模型系统怎么测？ | 功能、RAG 忠实度、工具轨迹、鲁棒性、安全、人审意识、延迟。 |
| 如何做压测？ | 先区分 API、RAG、LLM、工具、下载；再看 QPS、P95、错误率、资源。 |
| 工具失败怎么办？ | schema 拒绝、重试、熔断、reflection、人审。 |
| 如何定位一次错误回答？ | 数据层、切块层、召回层、重排层、生成层、质量门层逐级排查。 |
| 缓存怎么设计？ | key 由工具名和 payload hash 生成；TTL；命中率和失效策略写日志。 |

### 2.3 阿里 / 淘天 / 通义

高频画像：

- RAG 架构深挖：切分、召回、重排、向量库、混合检索、评估指标。
- 算法基础：机器学习、推荐、DIN、Wide&Deep、正则、编辑距离。
- 训练对齐：SFT、LoRA、DPO、PPO、GRPO、RLHF。
- 复杂项目：痛点、难点、优化效果、指标、取舍。
- SQL 和后端基础。

AuditPilot 推荐讲法：

> AuditPilot 当前重点是 Agent 应用工程，但我保留了训练数据收集和离线训练入口。实际落地顺序是先用评测和 badcase 沉淀数据，再判断是否需要 SFT/DPO。RAG 侧我采用混合检索，因为审计条款和控制编号对关键词很敏感，纯向量不够稳。

阿里高频追问与回答：

| 追问 | 回答抓手 |
| --- | --- |
| RAG 漏召怎么办？ | query rewrite、同义词、top-k、混合召回、知识补全、GraphRAG。 |
| RAG 错召怎么办？ | 重排、编号匹配、权威性分、来源过滤、质量门。 |
| 为什么不用纯向量？ | 审计标准编号、控制 ID、系统名需要精确匹配；混合检索更稳。 |
| SFT/DPO/PPO 怎么选？ | SFT 学示例；DPO 学偏好；PPO/RLHF 需要奖励和交互；项目当前先评测沉淀数据。 |
| 怎么量化 RAG 效果？ | Recall@k、Precision@k、MRR、NDCG、source coverage、faithfulness。 |

### 2.4 蚂蚁 / 合规风控 / 金融科技

高频画像：

- 合规、安全、权限、审计日志。
- 风险场景：误判、幻觉、高风险操作、人审。
- 业务系统工程：可追溯、可复核、可落地。
- 数据隐私：脱敏、权限隔离、删除、审计。

AuditPilot 推荐讲法：

> 审计/合规场景天然要求证据链和人工复核，所以 AuditPilot 的设计不是让模型直接给最终结论，而是让模型辅助取证、控制映射、风险识别和整改计划。低置信度、高风险、证据不足都会进入人审。

蚂蚁高频追问与回答：

| 追问 | 回答抓手 |
| --- | --- |
| 大模型幻觉导致合规风险怎么办？ | 来源绑定、质量门、missing evidence、人审、评测。 |
| 敏感数据如何处理？ | 上传限制、权限声明、环境变量、日志脱敏、生产权限系统。 |
| 如何追责？ | 审计 run、工具日志、复核记录、事件轨迹。 |
| 高风险操作能自动执行吗？ | 不能；必须 SafetyGate 和 Human-in-the-loop。 |
| 业务价值是什么？ | 提升审计取证、控制映射、整改跟踪和交付包生成效率。 |

## 5. 100 问中的 20 个必背标准答案

### 5.1 为什么 AuditPilot 不是 demo？

因为它有真实业务对象和持久化闭环：审计项目、控制矩阵、证据请求、整改任务、复核记录、报告、交付包、工具日志和评测记录都能创建、更新、下载和回放。

### 5.2 为什么自研 Runtime？

为了让任务协议、依赖、工具调用、反思、产物和指标可解释。生产复杂编排可迁移 LangGraph/Temporal，但业务 Agent 和 Skill 接口不需要重写。

### 5.3 为什么不用纯向量 RAG？

审计标准编号、控制 ID、系统名和证据名称需要精确匹配，纯向量容易语义相似但编号不准。混合检索更适合审计场景。

### 5.4 RAG 答错如何定位？

按数据、切块、召回、重排、生成、质量门逐级定位。先看 golden doc 是否存在，再看是否进 top-k，再看模型是否正确引用。

### 5.5 工具失败如何处理？

输入错误用 Schema 拒绝；暂时错误重试；连续错误熔断；关键工具失败进入 Runtime reflection；高风险进入人审。

### 5.6 如何控制幻觉？

来源绑定、置信度、质量门、missing evidence、人工复核和评测。证据不足时输出补证请求，不输出强结论。

### 5.7 如何做发布门禁？

比较当前评测和历史基线，检查整体分、通过率、质量回归、延迟回归和 blocker。失败则阻断发布。

### 5.8 如何优化评测速度？

预热、缓存、并行、增量评测、smoke/full 分层、异步后台任务和 case hash 缓存。

### 5.9 如何生产化？

文件 Repository 迁移数据库，对象存储保存文件，Redis 做缓存，Celery/Temporal 做任务，OpenSearch/ClickHouse 做日志，真实 MCP Server 接企业系统。

### 5.10 如何证明 Agent 有价值？

看是否减少审计师重复劳动，提升取证完整性、底稿一致性、整改跟踪效率和复核通过率，而不是只看回答是否漂亮。

## 6. 分公司最终背诵版

### 6.1 面字节时重点说

- Agent Runtime、Memory、MCP、RAG、FastAPI。
- 技术取舍：自研 Runtime vs LangGraph。
- 项目不是 demo：现场跑通闭环。
- 手撕要稳。

### 6.2 面腾讯时重点说

- 评测、压测、质量、日志、稳定性。
- 工具超时、熔断、降级。
- 大模型输出如何测试和定位。
- 后端基础要扎实。

### 6.3 面阿里/淘天时重点说

- RAG 架构、召回/错召/漏召、重排和指标。
- SFT/DPO/PPO/RLHF 的边界。
- 为什么当前是 Agent 应用工程，不是训练平台。
- 复杂项目的业务难点和优化路径。

### 6.4 面蚂蚁时重点说

- 合规、风险、人审、证据链。
- 敏感数据、权限、审计日志。
