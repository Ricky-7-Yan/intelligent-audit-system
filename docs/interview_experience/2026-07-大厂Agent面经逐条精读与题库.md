## 2. 逐条精读卡片

### 2.1 S01 字节 Agent 开发实习面经

面试题簇：

- Agent 开发框架：LangChain、LangGraph、AutoGen、CrewAI、Dify、Coze、OpenAI Agents SDK 这类框架分别解决什么问题。
- Memory：短期记忆、长期记忆、画像记忆、向量记忆、结构化记忆。
- 上下文压缩：窗口满了怎么压缩，如何保留有效信息，如何丢弃噪声。
- RAG：流程、实现方式、混合检索、重排、引用、评估。
- MCP：Host、Client、Server、Tools/Resources/Prompts，和 Function Calling 的区别。
- Skill：渐进式披露、技能描述、工具选择、上下文隔离。
- FastAPI：常用包、依赖注入、Pydantic、异步接口、上传下载、后台任务。
- A2A：Agent-to-Agent 协议或多智能体通信理解。
- 项目拷打：真实落地、怎么评测、哪里不是 demo。
- 手撕：螺旋矩阵。

AuditPilot 回答抓手：

- 框架题：不要只报框架名。可以说“我自研轻量 Runtime，但抽象上对应 LangGraph 的 state + node + edge；后续可迁移。”
- Memory 题：讲 `Working / Episodic / Profile / Related` 四层，说明为什么不是全塞向量库。
- 压缩题：讲摘要、重要实体保留、最近消息保留、风险/标准/系统名保留、低价值闲聊丢弃。
- RAG 题：讲切块、查询扩展、混合检索、来源、置信度、证据不足输出缺口。
- MCP/Skill 题：讲 `SkillRegistry` 的 Schema、权限、TTL、熔断、日志和 MCP-style 描述。
- FastAPI 题：讲 Pydantic Request Model、Jinja2 模板、静态资源、文件上传、报告下载、健康检查。

高概率追问：

- “你这个 Skill 和 Function Calling 有什么区别？”
  - Function Calling 是模型选择函数并生成参数的能力；Skill 是工程治理单元，包含描述、Schema、权限、缓存、熔断、日志和指标。
- “上下文压缩会不会丢关键信息？”
  - 会，所以要把信息分层：近期消息保序，审计实体结构化，历史摘要可追溯，必要时保留原始消息索引。
- “为什么不用 LangGraph？”
  - 当前项目要展示底层协议和状态，生产复杂编排可迁移；业务 Agent 和 Skill 接口不变。

需要补的基础：

- 螺旋矩阵、双指针、数组边界。
- FastAPI Depends、UploadFile、StreamingResponse/FileResponse、BackgroundTasks。
- MCP 基本架构和 Function Calling 区别。

### 2.2 S02 淘天 AI Agent 一面面经

面试题簇：

- 选择最复杂项目讲清痛点、难点、瓶颈、最终落地。
- Agent 任务目标拆解逻辑。
- PPO、RLHF、RM、Critic、DPO、GRPO、SFT、RAG 技术路线对比。
- RAG 项目初衷、整体架构、核心工作。
- 固定长度切分、语义切分、递归切分对比。
- 非结构化文档预处理。
- 向量数据库选型。
- 关键词检索 + 向量检索混合检索原因。
- 召回率、准确率等检索指标。
- 召回不足、匹配精度低、上下文关联差如何优化。
- 用户意图模糊、指代不清如何澄清。
- 重排序模型选型和横向对比。

AuditPilot 回答抓手：

- 项目痛点：审计不是聊天，必须有证据链、控制矩阵、整改闭环、人审和交付包。
- Agent 拆解：按产物拆，不按“人格”拆。Planning 产范围，Control 产矩阵，Evidence 产取证清单，Risk 产风险评分，Remediation 产整改计划，Quality Gate 产复核判断。
- 算法路线：AuditPilot 当前主线是 Agent 应用工程；SFT/RLHF/DPO/PPO/GRPO 可作为离线优化方向，不包装成已完成成果。
- 切分：当前按段落优先、长段滑窗；审计标准可按条款/控制编号进一步结构化切。
- 混合检索：审计里编号、标准条款、系统名、控制 ID 很关键，纯向量会漏精确 token。
- 意图模糊：先输出澄清问题或多候选意图，不直接强执行高风险工具。

高概率追问：

- “为什么你的项目不用 PPO/RLHF？”
  - 因为当前要解决的是企业审计流程可治理落地，不是基础模型对齐训练；RLHF 需要偏好数据和线上反馈闭环，目前项目保留离线训练入口，优先做评测和 badcase 沉淀。
- “RAG 怎么评价召回率？”
  - 需要 golden set：问题、标准答案、应召回文档 ID；指标看 Recall@k、MRR、NDCG、source coverage、faithfulness。
- “重排怎么做？”
  - 轻量可规则重排：控制编号/标准条款/领域词加权；生产可 Cross Encoder 或 LLM rerank。

需要补的基础：

- RLHF/PPO/DPO/GRPO/SFT/LoRA 的一句话原理和适用场景。
- Recall@k、Precision@k、MRR、NDCG。
- 向量库选型维度：规模、延迟、过滤、更新、权限、成本。

### 2.3 S03 淘天 AI Agent 二面面经

面试题簇：

- 详细介绍 RAG 项目整体架构和实现思路。
- 检索模块召回错误结果怎么办。
- RAG 漏召如何优化。
- RAG 效果怎么评估。
- LoRA 为什么低秩分解。
- DPO 输出变长原因和解决。
- 大模型复读机现象原因和解决。
- SFT 后通用能力遗忘怎么处理。
- Wide&Deep、DIN、L1/L2 正则、SQL、编辑距离。

AuditPilot 回答抓手：

- 错召：来源分数低、关键词不匹配、控制编号不一致时降权；加入重排和质量门。
- 漏召：增加 query rewrite、同义词、标准编号扩展、top-k、混合召回；补知识库。
- 评估：RAG evaluator 已看 term score、source score、authority、failure modes；生产扩展到人工 golden set。
- LoRA：如果被问训练基础，承认当前项目没有在线训练，但能说明离线训练入口和适用场景。
- 传统算法/SQL：准备编辑距离、HashMap、排序、窗口函数/聚合去重。

高概率追问：

- “检索结果错了，模型还会答错，你怎么防？”
  - 第一层重排过滤，第二层回答引用来源，第三层质量门识别证据不足，第四层评测记录 failure mode。
- “漏召是 query 问题还是知识库问题？”
  - 分诊：如果 golden doc 存在但没召回，是检索问题；如果知识库没有，是数据覆盖问题；如果召回但没用，是生成/重排问题。

需要补的基础：

- 编辑距离 DP。
- SQL 去重计数。
- L1/L2 正则区别。
- LoRA/DPO/SFT 遗忘基础。

### 2.4 S04 淘天 AI Agent 日常实习面经

面试题簇：

- 快排原理、时间复杂度、极端情况。
- HashMap 冲突解决。
- 场景题排序方案。
- 多轮对话存储、记忆解决方案。
- RAG 怎么设计。

AuditPilot 回答抓手：

- 多轮存储：`ConversationMemory` 按 session 存，保留 working messages、episodes、profile，后续可 Redis + DB。
- 记忆删除：项目已经做了记录治理，后续可以扩展用户记忆删除和隐私策略。
- RAG 设计：按前述 pipeline 讲，强调本地可运行和生产替换。

高概率追问：

- “记忆怎么避免越存越多？”
  - TTL/过期策略、摘要压缩、重要性评分、按业务实体归档、用户可删除。
- “HashMap 和你的项目有什么关系？”
  - 工具缓存、会话索引、run_id 索引都依赖 key-value 思路；生产考虑并发安全和过期策略。

需要补的基础：

- 快排退化与随机化/三数取中。
- HashMap 拉链法、开放寻址、扩容、负载因子。

### 2.5 S05 大模型应用面经合集

面试题簇：

- LLM 是怎么训练出来的。
- Transformer Encoder/Decoder。
- Function Call 如何训练或对齐。
- 微调方案。
- Tokenizer、Embedding。
- LangChain、AutoGen、LiteLLM。
- 为什么手搓 Agent，不用框架。
- MCP 和 Function Call 的区别，A2A 是否了解。
- ReAct、CoT、Few-shot、Prompt Caching、temperature/top-p/top-k。
- RAG：切分、多路召回、存储、数据库、GraphRAG、性能、幻觉、微调 vs RAG、量化效果。
- Workflow：任务拆分、效果提升。

AuditPilot 回答抓手：

- 手搓 Agent：为了展示状态协议、失败处理、工具治理和审计产物；不是排斥框架。
- Prompt Caching：项目里更直接的是 Skill TTL cache 和 evaluation cache；LLM prompt caching 可作为模型网关层优化。
- GraphRAG：审计领域适合实体关系，如系统、控制、证据、标准条款；当前保留可选知识图谱，生产可增强图谱召回。
- Workflow：审计任务天然是流程：立项、范围、取证、测试、发现、整改、复核、交付。

高概率追问：

- “CoT 为什么有效，为什么不能直接展示？”
  - CoT 增强中间推理，但生产不一定展示原始推理；更适合展示可审计步骤、证据和产物。
- “微调和 RAG 怎么选？”
  - 知识频繁变化、需要引用来源选 RAG；风格/格式/领域能力稳定优化可微调；强业务闭环要评测二者组合。

需要补的基础：

- Transformer Q/K/V、自注意力、位置编码。
- Tokenizer、Embedding、采样参数。
- ReAct、Plan-and-Execute、Workflow 的区别。

## 4. 高频题库：按模块细化

### 4.1 Agent 架构与规划

1. Agent 和 Workflow 的区别是什么？
2. ReAct、Plan-and-Execute、Reflection 分别适合什么场景？
3. Agent 什么时候需要 Planning，什么时候简单 Workflow 就够？
4. 任务拆解的粒度怎么定？
5. 任务执行失败如何恢复？
6. 怎么避免 Agent 无限循环？
7. 长周期任务怎么 checkpoint？
8. 多 Agent 如何分工？
9. 多 Agent 输出冲突怎么仲裁？
10. Verifier/Reviewer Agent 有什么价值？

AuditPilot 快答：

- 审计场景需要确定性交付链路，所以主流程是 Workflow + Runtime；只有在意图识别、证据检索、风险分析、整改建议等环节引入 Agentic 能力。
- 多 Agent 按产物拆分，最后 Quality Gate 收敛。
- Runtime 记录 plan、steps、artifacts、reflections、metrics，可用于失败恢复和回放。

### 4.2 Memory 与上下文

1. Memory 是什么？
2. 短期记忆和长期记忆怎么分？
3. 上下文窗口满了怎么处理？
4. 如何判断哪些信息该保留？
5. 记忆污染怎么防？
6. 用户要求删除记忆怎么办？
7. 画像记忆和情景记忆有什么区别？
8. 为什么不用一个向量库装所有记忆？
9. 多会话记忆怎么隔离？
10. 记忆如何参与工具调用？

AuditPilot 快答：

- Working Memory 保序，Episodic Memory 摘要，Profile Memory 结构化，Related Memory 召回。

- 生产演进要加过期、删除、脱敏、冲突检测。

## 5. AuditPilot 项目深挖回答模板

### 5.1 面试官：你项目里最难的点是什么？

推荐回答：

> 最难的不是调一个模型接口，而是把生成能力放进审计交付的可治理链路里。审计结论需要证据、控制、标准和复核，所以我设计了 Router、Memory、Runtime、RAG、Skill、Quality Gate 和 Evaluation 的闭环。每一步都要有产物、来源、失败处理和回归验证，否则它就只是一个回答生成器。

### 5.2 面试官：如果 RAG 答错了，如何定位？

分四段：

1. 数据层：知识库是否缺文档，文档是否过期。
2. 切分层：关键条款是否被切断。
3. 召回层：golden doc 是否进入 top-k。
4. 生成层：召回到了但模型是否忽略或误读。

对应 AuditPilot：

- 看 RAG sources、confidence、failure modes。
- 看 Quality Gate 的 missing evidence。
- 把 badcase 加入评测集。

### 5.3 面试官：你的系统如何证明可落地？

推荐回答：

> 我可以现场跑通：创建审计项目、生成控制矩阵和证据请求、上传证据分析、更新控制测试、提交复核、下载报告和交付包。运行记录、评测记录、工具日志和记忆都持久化，不是静态页面。项目也支持无 LLM key 的确定性降级，所以可运行性不依赖外部模型是否可用。

### 5.4 面试官：生产上你会怎么改？

分层回答：

- 数据：文件 Repository → PostgreSQL/MySQL + 对象存储。
- 异步：本地执行 → Celery/Temporal/Kafka。
- RAG：本地 store → pgvector/Milvus/OpenSearch + reranker。
- 工具：MCP-style → 真实 MCP Server。
- 安全：简单 SafetyGate → 权限系统、审计日志、敏感操作确认。
- 观测：JSONL 日志 → Trace + Metrics + Dashboard。
- 评测：内置样例 → golden set + 线上反馈 + badcase 自动归类。
