# 审脉 AuditPilot 架构与设计

## 1. 产品定位

审脉不是“输入一句话、输出一段报告”的聊天 Demo，而是一个面向 IT 审计、内控、数据安全与合规团队的 Agent 交付系统。核心对象是审计项目，不是聊天消息。

主业务链：

```text
立项 -> 范围 -> 取证 -> 控制测试 -> 风险与发现 -> 整改 -> 人工复核 -> 报告与交付包
```

Agent 工程链：

```text
意图路由 -> 记忆读取 -> 任务规划 -> RAG/工具调用 -> 反思与质量门 -> 人工复核 -> 评测回归
```

## 2. 分层架构

### 产品层

- `templates/`、`static/`：工作台、审计项目、Agent 协作、知识与证据、运行时、评测与发布。
- `web/main.py`：页面路由、Pydantic 请求模型、FastAPI API 和依赖注入。

### Agent 层

- `agents/audit_agent.py`：范围、检索、控制映射、风险、程序、抽样、发现、质量门和整改主链。
- `services/intent_router.py`：Pattern + 本地 n-gram 语义相似度融合路由。
- `services/conversation_memory.py`：工作、情景和画像三层记忆。
- `services/agent_runtime.py`：协议化任务、依赖计划、步骤、产物、重试、反思与检查点。
- `services/skill_registry.py`：Skills/MCP 工具治理。
- `services/safety_gate.py`：敏感输入、破坏性动作、证据不足和人工复核门禁。

### 知识与数据层

- `rag/agentic_rag.py`：切块、持久化、混合召回、查询扩展、来源引用和降级检索。
- `knowledge_graph/`：知识实体关系与 Neo4j 可选接入。
- `services/evidence_analyzer.py`：CSV/TSV/JSON/日志/文本证据画像与风险信号。
- `services/*_repository.py`：审计、评测、运行时和证据分析的持久化。

### 评测与交付层

- `training/training_pipeline.py`：Agent 评测集、响应与轨迹指标。
- `services/rag_evaluator.py`：RAG 相关性、忠实度、引用和失败模式。
- `services/evaluation_repository.py`：基线差异、回归检测和发布门禁。
- `services/audit_delivery.py`：底稿索引、证据、测试、访谈、日程、发现和事件轨迹。

## 3. 一次 Agent 请求

1. Router 输出 `intent`、`confidence`、`urgency`、实体、候选 Agent 和协作策略。
2. Memory 读取当前会话最近消息、历史摘要、相关消息和审计画像。
3. AuditAgent 生成任务计划，并从 RAG、内置标准、可选 MySQL/Neo4j 读取依据。
4. 控制映射器生成控制目标、证据要求和测试程序。
5. 风险引擎结合风险关键词、控制成熟度和证据质量计算剩余风险。
6. 质量门输出置信度、证据缺口、是否允许自动继续和人工复核条件。
7. 结果写入持久化记忆；审计项目请求还会写入档案、整改任务和交付包。

## 4. Agent Runtime 协议

任务包 `audit-agent-task-v1` 包含：

- `objective`、`context`：目标与审计上下文。
- `plan`：步骤、依赖、Agent 角色、Skill 和用途。
- `steps`、`tool_calls`：执行结果、重试、缓存、熔断和耗时。
- `artifacts`：每一步形成的可交付产物。
- `reflections`：步骤结论、置信度、问题与下一动作。
- `safety_gate`、`budgets`：安全状态和工具/重试预算。
- `metrics`：成功、失败、缓存命中、重试和延迟。

默认角色为 Planning、Control、Evidence、Remediation；审计主 Agent 还包含 Risk、Compliance 和 Quality Gate。

## 5. 可用性与降级

- 没有 LLM：使用确定性审计逻辑生成结构化结果。
- 没有向量模型：使用本地词项与 n-gram 信号。
- 没有 MySQL/Neo4j：使用内置标准和本地图结构。
- 工具输入错误：Schema 验证直接拒绝。
- 工具超时/失败：重试、熔断并进入反思或人工复核。
- 证据不足：不输出强结论，生成补证请求。

## 6. 安全与审计

- 密钥只从环境变量读取，`config.env` 不进入 Git。
- 上传类型和大小受限；证据分析不执行上传内容。
- 工具声明权限和输入 Schema，调用结果写入 JSONL。
- 所有审计项目、控制测试、复核和整改更新保留事件轨迹。
- 高风险、低置信度和证据不足由 Human-in-the-loop 处理。

## 7. 设计取舍

- 采用自研轻量 Runtime，便于面试中解释 Plan/Execute/Reflect 的底层状态，而不是只展示框架调用。
- 默认文件持久化使项目可直接运行；生产环境可将 Repository 接口迁移到 PostgreSQL/MySQL、对象存储和队列。
- 前端保持无构建依赖，便于部署演示；核心业务逻辑全部在 API，后续可平滑换成 React/Vue。
