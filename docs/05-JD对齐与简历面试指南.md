## 1. 公开 Agent JD 高频要求

2026 年公开岗位信息中，字节、腾讯、阿里相关 Agent 岗位反复出现：

- Planning、Memory、Reflection、多步调度与 Multi-Agent。
- RAG、Knowledge、查询改写、重排、忠实度和幻觉控制。
- Tool Use、Function Calling、MCP、Skills 与外部 API/数据库。
- 评测集、离线回归、LLM-as-Judge、置信度、Badcase 和发布门禁。
- 可观测、缓存、超时、熔断、降级、安全和 Human-in-the-loop。
- Python/Go/Java 工程能力、FastAPI/微服务、Docker 和系统设计。
- 真实业务场景的端到端交付，而不是框架拼接。

公开参考：

- 字节 Agent 核心架构类岗位：Planning、Memory、Reflection、多 Agent、Skills/Tools、RAG 与端到端落地。

## 3. 简历项目描述

### 一句话

审脉 AuditPilot 是一个面向 IT 审计交付的企业级 Agent 平台，集成融合意图路由、分层记忆、多 Agent 任务编排、Agentic RAG、Skills/MCP 工具治理、风险质量门、人工复核和评测发布闭环。

### 推荐 Bullet

- 设计 Pattern + 本地 n-gram 语义相似度的融合路由，输出意图、置信度、紧急度和实体，并对跨证据/控制/整改请求触发多 Agent 协作。
- 实现工作记忆、情景摘要和审计画像三层 Memory，支持会话压缩、相关历史召回和服务重启后的上下文恢复。
- 自研 Plan/Execute/Reflect Agent Runtime，以依赖计划驱动 Planning、Control、Evidence、Remediation Agent，持久化步骤、产物、重试和反思。
- 建设 Skills/MCP 工具层，提供输入 Schema、权限、超时、TTL 缓存、熔断、调用日志和 P95 延迟等治理能力。
- 将 Agentic RAG 接入审计主链，融合企业知识、标准库、控制库和可选知识图谱，输出来源、证据缺口与质量置信度。
- 构建 Agent/RAG/Deep Research 评测与发布门禁，比较历史基线并检测质量、通过率和延迟回归。
- 落地审计项目闭环，覆盖立项、证据文件分析、控制测试、抽样、发现、整改、人工复核和交付包。

## 4. 30 秒 Pitch

我做的不是聊天机器人，而是审计交付 Agent。请求先经过可解释的融合路由和三层记忆，再进入自研 Plan/Execute/Reflect Runtime；不同 Agent 通过受治理的 Skills/MCP 工具调用 RAG、控制库和证据分析。系统会把证据不足变成补证任务，把低置信度和高风险交给人工复核，并用评测基线和发布门禁防止回归。最终产物是控制矩阵、底稿、发现、整改和交付包，而不只是一段回答。

## 5. 高频面试题

### 为什么不只用 LangGraph？

项目保留了自研 Runtime，使任务协议、依赖、重试、反思、工具状态和持久化可直接解释；如果生产规模需要分布式状态机，可把相同节点迁移到 LangGraph/Temporal，而业务 Agent 和 Repository 不需要重写。

### 多 Agent 如何避免“为了多而多”？

Router 只有在候选意图分数达到协作阈值时才选择多个 Agent；每个角色绑定不同输入、Skill 和产物，最终由质量门和人工复核统一收敛。

### 记忆为什么不用纯向量库？

近期消息、历史事件和长期画像的生命周期、查询方式和隐私边界不同。Working 需要顺序，Episodic 需要摘要与相关召回，Profile 需要结构化更新，混在一个向量 Collection 会导致检索噪声和难以删除。

### 如何控制幻觉？

答案以 RAG/标准/控制/证据为依据；质量门检查来源、证据和置信度；缺失证据会生成任务，不允许自动形成强结论；高风险进入人工复核。

### 如何证明不是 Demo？

现场创建审计项目、更新控制测试和证据状态、提交复核、下载交付包；再创建 Runtime 任务查看工具调用和反思，最后运行评测观察基线差异。

## 6. 真实性边界

- 不声称未经压测的并发、P95 或可用性。
- 不把内置评测集分数包装成线上业务准确率。
- 文件 Repository 是可运行实现，不等同于最终大规模数据库方案。
- SFT/RLHF 为离线训练方向，当前 Web 主链重点是可评测的 Agent 应用工程。
