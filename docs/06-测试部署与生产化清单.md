## 2. 本地与容器部署

本地：

```powershell
python start.py
```

Docker：

```powershell
docker build -t auditpilot:4.0 .
docker run -d --name auditpilot -p 8000:8000 --env-file config.env `
  -v ${PWD}\data:/app/data -v ${PWD}\logs:/app/logs auditpilot:4.0
```

## 4. 生产化演进

### P0：真实内部试点

- PostgreSQL/MySQL 替换 JSON Repository。
- Redis 工作记忆和分布式锁。
- Celery/RQ/Kafka/Temporal 承载长任务。
- 对象存储保存证据原件和哈希。
- SSO、RBAC、租户和项目数据隔离。

### P1：可靠性

- SSE/WebSocket 流式轨迹。
- 模型网关：多模型路由、重试、限流、成本预算。
- OpenTelemetry Trace、Prometheus 指标、结构化日志和告警。
- 工具幂等键、补偿事务、死信队列。
- Prompt/Skill 版本和灰度发布。

### P2：效果与自进化

- 审计 Golden Set、专家双盲标注。
- Retrieval Recall@K、MRR、NDCG 和引用正确率。
- LLM-as-Judge 与规则 Judge 交叉验证。
- Badcase 聚类、根因标签和自动生成回归用例。
- 线上 A/B、置信度校准和人工接管率。

## 5. 性能建议

- 知识检索与图谱查询并发执行。
- 对相同 RAG 问题使用 TTL 缓存。
- 长文档异步切块与嵌入。
- LLM 输出使用流式响应。
- 审计项目列表使用数据库索引和分页。
- 大规模评测按用例并发，但限制模型 QPS。

## 6. 数据与合规

- 证据文件按项目和租户隔离，并记录 SHA-256。
- 日志脱敏，不记录密钥、身份证、银行卡等敏感字段。
- 用户可删除会话 Memory 和上传证据。
- 模型供应商、数据跨境和保留期限需符合企业政策。
- AI 输出始终标记为审计建议，最终结论由授权审计人员签署。
