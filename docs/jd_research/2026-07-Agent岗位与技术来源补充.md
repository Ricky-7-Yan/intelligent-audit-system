# 2026-07 Agent 岗位与技术来源补充

> 本文用于补充 `docs/08-大厂Agent JD与能力映射.md` 与 `docs/12-Agent市场关注方向内部参考.md`。不展示在客户产品页面。

## 01 查询结论

本轮优先参考官方工程文档、协议规范和行业调研材料。大厂岗位 JD 页面经常动态更新、下线或需要站内脚本渲染，因此本轮记录“岗位能力方向 + 可验证技术来源”，避免把不可稳定访问的页面当作唯一依据。

## 02 对岗位能力的补充判断

| 能力方向 | 岗位/JD 常见表述 | 项目当前证据 | 继续增强方向 |
| --- | --- | --- | --- |
| Agent 工程化 | Agent Runtime、任务编排、多步骤执行、运行状态管理 | `services/agent_runtime.py`、`/skills` 运行时中心 | 长周期任务恢复、任务版本对比、失败回放 |
| Tool Use / MCP | 工具调用、函数调用、外部系统连接、权限与安全 | `services/skill_registry.py`、`/api/mcp/tools`、工具日志 | 接入真实 MCP Server、工具选择准确率、敏感操作确认 |
| RAG / Deep Research | 检索增强、来源融合、引用追踪、多轮研究 | 知识与证据页、Deep Research、RAG 评测 | 来源权威性打分、证据冲突检测 |
| Evaluation / Harness | 离线评测、回归测试、发布门禁、badcase 沉淀 | 评测与发布门禁页、`EvolutionHarness` | Bad Case 自动分类、失败样例进入训练/评测集 |
| Observability | Trace、日志、性能指标、可解释执行过程 | Agent Runtime、Skill runs、全局命令中心 | Trace 可视化、按失败原因检索 |
| Human-in-the-loop | 人工复核、审批、风险升级、操作确认 | 审计复核、质量门、证据请求、下载交付包 | 高风险工具调用审批流 |
| Self-Evolution | 经验沉淀、自动改进提案、持续学习 | Self-Evolution Control Plane、提案物化任务 | 经验单元评分、记忆污染检测、自动回滚建议 |

## 03 本轮新增项目能力对应

新增全局命令中心后，项目在“成熟产品可用性”和“运行治理”上有新的表达点：

- 支持 Ctrl/⌘ + K 快速检索。
- 聚合审计项目、评测记录、证据分析、运行任务、工具日志。
- 支持从搜索结果深链接打开具体记录。
- 降低多页面、多记录、多工具带来的认知负担。

面试表达可以概括为：

> 我不只是做了 Agent 的生成能力，也做了运行治理层：评测、发布门禁、工具日志、证据记录、任务追踪都可以被统一检索和回放，便于企业场景里的审计、复核和持续改进。
